#87 指标体系 中等

人均 GMV 涨了、总 GMV 没涨，算变好吗？人均指标怎么定义、异常用户怎么处理？

人均指标ARPU分母对齐异常值截尾客单价

🎯 考察意图

考察候选人会不会把人均当成独立的「好分数」，还是能拆成「总量 / 人数」这一比率。要能锁分母集合、对齐窗口与成功态，并处理头部用户把均值拽歪。只会报一个平均数、删大客对总量、或拿注册用户去除以支付 GMV，这题就浅了。

📐 回答框架

  1. 先给定义：人均是比率，不是第三种独立指标；先写清分子、分母、窗口。
  2. 钉分母：活跃用户、付费用户、下单用户、注册用户，四种人均完全不是一个数。
  3. 解释「人均涨、总量平」的三种机制：人变勤、分母变少、头部把均值拽高。
  4. 处理异常：看分位数、封顶后再平均；大客切片而不是从总量里偷删。
  5. 收口：看板同时报总量、人均、p50/p90；口径写进说明书，禁止只报一个均值。

💬 参考答案（口述版）

一句话：人均 GMV 是比率，等于窗口内 GMV 除以窗口内那群人。人均涨、总量没涨，优先怀疑分母变少或头部用户把均值拽歪，不要直接当产品变好。

先把公式写死，口述从这里开始。

人均 = 窗口内分子 / 窗口内分母人数

分子、分母必须同窗口、同时区、同成功态。分母必须是「有资格产生这个分子」的集合。写不出分母，就不要报人均。

常见三套分母，名字都叫人均，数差一截：
- ARPU（每用户平均收入/GMV）：分母 = 窗口内活跃用户（先锁活跃定义）
- ARPPU（每付费用户）：分母 = 窗口内至少付过一次的人
- 客单价 AOV：分母 = 订单数，不是人数；量纲是「每单」不是「每人」
还有一种更虚的：注册用户做分母。大量从未回来的人把人均打穿，环比会随注册活动乱跳。

「人均涨、总量平」通常只有三种机制，面试要主动拆。
1. 人变勤：同样那群人，频次或件单价上去了。总量也该涨；若总量完全不动，这条往往不成立，要核是不是口径窗口不同。
2. 分母收缩：低活用户流失、活跃口径改严、过滤了新客或未登录。剩下的人更「肥」，人均涨、总量持平甚至微跌。这是结构变化，不是体验变好。
3. 头部拉动：几个 KA、刷单号、内部测试账号、一次异常大单，把均值拽上去；中位数和 p90 没动。均值对长尾分布极敏感。

拆的时候不要只看一个数：

SELECT
  dt,
  SUM(gmv) AS gmv,
  COUNT(DISTINCT user_id) AS users,
  SUM(gmv) * 1.0 / NULLIF(COUNT(DISTINCT user_id), 0) AS arpu,
  APPROX_PERCENTILE(user_gmv, 0.5) AS p50,
  APPROX_PERCENTILE(user_gmv, 0.9) AS p90
FROM (
  SELECT dt, user_id, SUM(gmv) AS user_gmv
  FROM dws_user_pay_daily
  WHERE dt BETWEEN '2026-11-01' AND '2026-11-28'
  GROUP BY 1, 2
) t
GROUP BY 1;

人均动了，先看 users 变没变、p50 变没变，再解释 ARPU。

异常用户怎么处理，说明书里要写死。
- 先看分布，不要先删数。p99 之外是谁：KA、渠道刷量、内部账号、一次企业大单？
- 封顶后再平均：单用户 GMV 截到 p99（或业务封顶额）再算「截尾人均」，看板标题写清楚。总量仍报全量，财务和对账不能丢大客。
- 切片，不要偷删：KA / 企业购单独一条线；C 端人均看 C 端。从全量里默默 WHERE gmv < 10000，历史对比全部作废。
- 排除名单：测试号、内部员工、已知刷单，进名单并写进指标说明书；进名单要有主人，不能分析师临时滤。
- 中位数不是人均的替代品：业务要的是「钱从哪来」，均值回答贡献，中位数回答「典型用户」。两个都报。

分子分母对齐的硬规则。
- 禁止金额除以次数还叫人均：支付 GMV / 曝光次数是「曝光效率」，不是人均。
- 禁止跨成功态：分子用支付成功，分母用「打开过 App」可以（ARPU 常见），但必须声明；分子用成交 GMV、分母用下单用户，中途取消的人会把人均拉歪。
- 窗口对齐：月 ARPU 的分母是月活，不是把每天 ARPU 再平均一遍（那是日 ARPU 的平均，被日活波动加权）。正确是月 GMV / 月活人数。
- 人均本身不可加：部门 A 人均 + 部门 B 人均 ≠ 整体人均。整体必须用总量重算，或按人数加权。这点和半可加/不可加指标是同一类坑。

口述案例：周报人均 GMV 120→150，总 GMV 几乎没动。拆开发现周活从 80 万掉到 64 万，p50 没变，p99 从 800 涨到 4000——一个渠道的两个刷单号贡献了 8% GMV。结论：不是变好，是分母掉了加头部污染。动作：刷单进排除名单；看板加截尾人均和周活；跟业务讲的是「有效周活和 C 端 p50」，不是那一个 150。

收尾：面试官要听「人均是比率 → 先锁分母 → 涨跌拆成人数/头部/真变勤 → 截尾与切片，总量不偷删」。能主动说月人均不是日人均的平均，这题就过了。

🔍 关键词

人均ARPUARPPU分母对齐截尾客单价

💭 面试官可能的追问

追问 1：ARPU、ARPPU、客单价分母分别是谁？业务说「人均客单」你怎么接？

ARPU 分母是窗口内活跃用户，含没付钱的人，所以会被拉新和未转化砸低。ARPPU 分母是付过钱的人，看付费人群的客均贡献。客单价分母是订单数：同一人一周下三单，客单价看三单平均，ARPPU 看这人一周合计。业务口中的「人均客单」经常把这三套混在一句里。接法：先复述三种分母，问他要的是「人均花了多少」还是「每单多少钱」；指标说明书里三个名字分开，禁止一个中文名三套公式。

追问 2：要不要用中位数替代人均？截尾均值怎么进看板才不和财务对不上？

中位数回答典型用户，人均（均值）回答钱从哪来。只报中位数会把头部贡献藏起来，只报均值会被羊毛党带节奏，两个都要。截尾均值是分析口径：单用户封顶后再平均，标题必须带「截尾」。财务 GMV、对账、OKR 主指标用全量；截尾人均当解读指标，不能替代总盘。封顶阈值写进说明书（p99 或固定额），变更要双跑，不能这周 p99 下周 p95。

追问 3：大促拉来一波低价新客，人均掉了，怎么跟业务解释、指标要不要改分母？

这是分母膨胀，不是老客变穷。先切片：新客人均、老客人均、新客人数占比。老客人均稳住、新客把整体均值拉低，是拉新结构，不是体验事故。分母不要为了「好看」改成只含老客——那叫换指标。正确做法是同时报：总 GMV、整体 ARPU、新/老 ARPU、新客占比。评价大促看增量 GMV 和这些新客的次周留存，不看整体人均是否创了新高。

⚠️ 常见踩坑

  • 把人均当成独立分数，不拆「总量 / 人数」，人均涨就报喜
  • 分母用注册用户或曝光次数，和支付 GMV 量纲不对齐还叫人均
  • 从总量里偷偷过滤大客/刷单，财务和对账对不上，历史环比作废
  • 只报均值不看 p50/p90 和人数，被两三个异常账号带节奏
  • 把每天 ARPU 再平均当成月 ARPU，等于用日活给人均做了错误加权
  • 部门人均相加当整体人均，忽略人均不可加，必须用总量重算

🧠 记忆锚点

人均是比率：先锁同分母，再看是人变勤、人变少，还是大客把均值拽歪；总量和分位数一起报，不要只报一个平均数。
