#12 业务分析 中等

如何做转化漏斗分析？转化率掉了怎么拆？

漏斗归因切片

🎯 考察意图

业务数据分析经典题。考察结构化拆解能力与「先定义步骤再取数」。

📐 回答框架

  1. 定义步骤与时间窗、是否同一会话。
  2. 算各步转化与最长瓶颈步。
  3. 切片：渠道/人群/平台/版本。
  4. 结合定性：可用性、供需、价格、性能。

💬 参考答案（口述版）

漏斗分析步骤：
1. 与产品对齐步骤定义（如曝光→点击→下单→支付）及成功事件
2. 明确是否要求严格有序、时间窗（当日/7 日内）、用户级还是会话级
3. 计算每步人数与步间转化率，定位最大掉失步
4. 多维拆解：新老、渠道、机型、地区、价格带、实验组
5. 形成假设并验证（改文案/性能/库存/支付方式），能实验就实验

掉量排查顺序：数据口径与埋点是否变 → 大盘流量结构是否变 → 单步技术故障（白屏/接口）→ 供需与竞争 → 产品策略。

加分：区分「整体转化」与「同队列转化」；避免把非同一批用户硬比。

🔍 关键词

💭 面试官可能的追问

追问 1：为什么各步 UV 加总会对不上？

因为用户可跨天、可跳步、可多会话；漏斗是条件路径计数，不是互斥分割。

⚠️ 常见踩坑

  • 步骤定义含糊，不同人算出不同转化
  • 只看总转化，不拆结构变化

🧠 记忆锚点

先对齐漏斗定义；掉了先找最大掉失步，再切片验证假设。
